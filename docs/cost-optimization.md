# 비용 최적화 사례

## 1. DynamoDB — 사용 패턴 기반 과금 모델 전환

### 문제 인식
4월 청구서 분석 중 DynamoDB 항목이 약 $92로 잡힘 → 평시 트래픽 대비 과다.

### 분석
- 티켓팅 도메인 특성: **이벤트 오픈 시점 burst + 평시 거의 idle**
- 기존 설정: Provisioned WCU 20,000 상시 할당
- 실제 사용률: 평시 1% 미만

### 적용
```
평시: On-Demand 모드 (사용량 기반)
이벤트 직전 (T-30분): EventBridge → Lambda → UpdateTable → Provisioned 전환
이벤트 종료 후 (T+30분): Lambda → On-Demand 복원
```

### 결과
- 평시 과금: 사용량 기반으로 전환
- Burst 대응력: 유지
- 자동화로 운영 부담 0

## 2. NAT Gateway — VPC Endpoint 도입으로 트래픽 절감

### 문제 인식
EKS 노드 → AWS API 호출이 전부 NAT Gateway 경유 → 트래픽 비용 + 레이턴시 누적

### 적용
| Endpoint | 종류 | 효과 |
|---|---|---|
| ECR API | Interface | 이미지 메타데이터 |
| ECR DKR | Interface | **이미지 레이어 Pull (트래픽 큼)** |
| STS | Interface | IRSA 토큰 발급 |
| SSM | Interface | Parameter Store 조회 |
| S3 | Gateway | 무료, S3 트래픽 내부화 |

### 결과
- 큰 트래픽이 VPC 내부 경로로 전환
- NAT Gateway 트래픽 비용 절감
- 외부 PG 호출만 NAT 경유 유지 (불가피)

## 3. CloudWatch — 모니터링 강화하면서 비용 통제

### 동기
스케일링 반응성을 개선하기 위해 고해상도 메트릭(StorageResolution: 1) 도입 검토 → **추가 비용이 어느 정도인지 사전 검증** 필요

### 사전 비용 분석
- 고해상도 메트릭: 표준 메트릭 대비 단가 5배
- 메트릭 종류 × 발행 주기 × 데이터 포인트 수 계산
- **예상 추가 비용: 월 $2~3 수준** → 도입 결정

### 결과
- 파이프라인 약 36초로 단축
- 추가 비용은 예상 범위 내 통제

**핵심**: "관찰 가능성 강화 = 무조건 비용 증가" 아니라, **얻는 가치 대비 비용을 사전 계산하면 합리적 의사결정 가능**

---

## 4. 모니터링 인프라 — EKS 외부 EC2 1대로 충분

### 결정
Prometheus + Grafana + Loki를 별도 EC2 (t3.small)에서 운영

### 비용
- AWS Managed Prometheus(AMP) + Managed Grafana(AMG) 대비 **수십 분의 1 수준** 비용
- 단일 EC2의 한계는 있지만, 부트캠프 규모 트래픽엔 충분

### 트레이드오프
- ❌ HA 부족 (단일 EC2)
- ✅ 비용 절감 + EKS 외부 분리로 클러스터 장애 시에도 관찰 가능

---

## 5. 청구서 분석 루틴

### 배경
크레딧이 적용되어 실제 지출이 가려져 있던 시기엔 비용 패턴이 안 보임 → 4월에 크레딧 소진 후 갑자기 청구서가 뛰면서 발견

### 적용
- **매주 Cost Explorer로 항목별 지출 점검**
- AWS Budgets 알람 설정 (월 예산의 50%/80%/100% 단계별)
- 크레딧 의존도와 실지출을 분리해서 추적

### 결과
- 4월 청구서 약 $335 급등 시점 조기 포착
- 이후 비용 누수 패턴을 사전에 발견하는 루틴 정착

## 종합 절감 효과

| 영역 | Before | After |
|---|---|---|
| DynamoDB | Provisioned 20k WCU 상시 ($92) | On-Demand 기본 + 자동 전환 (사용량 기반) |
| NAT 트래픽 | 모든 AWS API 호출 NAT 경유 | 큰 트래픽 4종 VPC Endpoint로 내부화 |
| 모니터링 | (AMP + AMG 사용 시) ~$30+/월 | 자체 EC2 t3.small (~$10/월) |
| CloudWatch 메트릭 | 표준 (느림) | 고해상도 + 비용 통제 ($2~3 추가) |

**핵심 원칙**: "기능을 줄여 비용을 줄인 게 아니라, **사용 패턴에 맞게 과금 모델·구성 방식을 바꿨다**."
